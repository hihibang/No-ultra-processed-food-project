| 항목 | sample7.md 표현 | 실제 현재 상태 | 처리 방침 |
|---|---|---|---|
| 토큰 저장 | "localStorage/Cookie 동기화" | `LoginForm`이 `access_token`, `user_info`를 **localStorage**에 저장. 쿠키는 저장하지 않음 (`AuthContext.logout`만 쿠키 삭제 시도) | **localStorage만 사용**. 쿠키 동기화는 추가하지 않음 |
| 인증 헤더 | 언급 없음 | `/api/auth/me`, `PUT /api/auth/me`는 로그인 사용자 식별이 필요하지만 현재 백엔드에 토큰 검증 의존성 없음 (`auth_utils.py`는 발급만 함) | `Authorization: Bearer` 토큰을 디코딩하는 `get_current_user` 의존성 추가 |

| 프로필 요약 | 이름, 숙련도, 칩 요약 | `AuthContext.user`에 `user_id, email, name, appliances, preferences, cooking_level` 포함 | 로그인 시 받은 `user`를 초기값으로 사용하고, 마운트 시 `GET /api/auth/me`로 최신화 |

## 🏗️ 백엔드 작업

### 1. schemas (`server/schemas/user_schema.py`)
- `ProfileUpdateRequest`
  - `name: str` (1~100자, 공백만 입력 불가)
  - `appliances: List[str]`
  - `preferences: List[str]`
  - `cooking_level: str` (허용 값 검증: `beginner` / `intermediate` / `advanced`)

### 2. models (`server/models/user_model.py`)
- `find_by_id(session, user_id) -> Optional[dict]`
  - `find_by_email`과 동일한 컬럼 구성, `WHERE user_id = :user_id`
- `update_profile(session, user_id, data: ProfileUpdateRequest) -> None`
  - `UPDATE users SET name = :name, appliances = :appliances, preferences = :preferences, cooking_level = :cooking_level, updated_at = CURRENT_TIMESTAMP WHERE user_id = :user_id`
  - JSON 컬럼은 `json.dumps(..., ensure_ascii=False)`로 직렬화 (회원가입과 동일 방식)
  - `commit` 후 반환 없음 → 라우트에서 `find_by_id`로 최신값 재조회
- 기존 `_format_row`, `_load_json_list`를 재사용

### 3. utils (`server/utils/auth_utils.py`)
- `decode_access_token(token) -> int` : `JWT_SECRET_KEY`로 검증, `sub`를 `user_id`(int)로 반환. 만료/위조 시 예외
- `get_current_user(credentials, db)` FastAPI 의존성
  - `HTTPBearer` 사용 → `Authorization: Bearer <token>` 파싱
  - 토큰 검증 후 `UserModel.find_by_id`로 사용자 조회
  - 사용자 없음 또는 `is_active = 0`이면 401
  - 반환값: 사용자 dict (또는 `UserResponse` 변환 헬퍼)
- 토큰 실패 메시지: "인증 정보가 올바르지 않습니다. 다시 로그인해 주세요."

### 4. routes (`server/routes/auth_routes.py`)
- `GET /api/auth/me` (`response_model=UserResponse`)
  - `Depends(get_current_user)`로 본인 정보 반환
- `PUT /api/auth/me` (`response_model=UserResponse`)
  - 요청: `ProfileUpdateRequest`
  - 처리: `update_profile` → `find_by_id` 재조회 → `UserResponse` 반환
  - 본인 외 사용자 정보 수정 불가 (user_id는 토큰에서만 취득, 요청 본문으로 받지 않음)

### 5. 백엔드 검증
- `uvicorn main:app` 기동 후 `/docs` 또는 curl로 확인
  - 로그인 토큰 없이 `GET /api/auth/me` → 401
  - 잘못된 토큰 → 401
  - 정상 토큰 → 200, `password` 미포함
  - `PUT /api/auth/me`로 이름/주방기기/취향/숙련도 변경 → 200, 응답 값 및 DB 값 일치
  - `cooking_level`에 허용되지 않은 값 → 422
  - 빈 이름 → 422
- 테스트용 사용자는 생성 후 반드시 삭제 (DB 정리 확인)

## 🎨 프론트엔드 작업

### 1. AuthContext / CartContext 보강
- `AuthContext.jsx`
  - `updateUser(partialOrFullUser)`: `setUser` + `localStorage.setItem('user_info', ...)` 동시 갱신
- `CartContext.jsx`
  - `removeFromWishlist(productId)` 추가 (`toggleWishlist`와 동일 패턴으로 `filter`)
  - `value`에 `removeFromWishlist` 노출
  - 장바구니 로직은 수정하지 않음

### 2. API 호출 헬퍼
- 기존 `fetch` 직접 호출 패턴을 따름 (`CatalogPage.jsx`, `LoginForm.jsx`와 동일하게 `API_BASE_URL = 'http://127.0.0.1:8000'`)
- 인증 필요 요청은 `localStorage.getItem('access_token')`을 `Authorization: Bearer` 헤더에 포함
- 401 응답 시: `logout()` 호출 후 로그인 모달 안내 또는 홈으로 이동

### 3. MyPage (`front/src/pages/MyPage.jsx`)
- 비로그인 상태 접근 시: 안내 문구와 홈 이동 버튼 표시 (`isLoggedIn` 확인)
- 마운트 시 `GET /api/auth/me` 호출 → 성공 시 `updateUser`로 최신화, 실패 시 기존 `user` 값 유지
- 쿼리 파라미터 `?tab=wishlist` 지원 (`/wishlist` 리다이렉트 용도), 기본 탭은 개인화 설정

**상단 프로필 요약 카드**
- 이름, 이메일, 요리 숙련도 라벨(초보/중급/고수)
- 보유 주방기기·선호 요리 칩 요약 (최대 n개 표시, 나머지는 "외 n개")

**탭 1: 개인화 설정**
- 이름 입력창 (빈 값 검증)
- 보유 주방기기 칩 토글 (`전자레인지, 에어프라이어, 인덕션, 가스레인지, 오븐, 믹서기` — `SignupForm.jsx`와 동일 목록 사용)
- 선호 요리 스타일 칩 토글 (`한식, 양식, 중식, 일식, 베이킹, 건강식`)
- 요리 숙련도 선택 (`beginner` → 초보 / `intermediate` → 중급 / `advanced` → 고수)
- 칩/옵션 목록은 `SignupForm.jsx`와 중복되므로 `front/src/constants/userOptions.js`로 분리 후 양쪽에서 import 권장
- "저장하기" 클릭 → `PUT /api/auth/me`
  - 성공: `updateUser(응답 user)` → 토스트 "개인 정보가 저장되었습니다." 표시
  - 실패: 서버 `detail` 또는 기본 메시지 토스트, 입력값 유지
- 변경 사항 없을 때 저장 버튼 비활성화 (선택 사항)

**탭 2: 위시리스트 관리**
- `useCart()`의 `wishlist`, `wishlistCount`, `removeFromWishlist` 사용
- 상품 카드 그리드: 이미지, 상품명, 가격, 주요 정보 (필드명은 착수 시 `ProductCard.jsx` 기준 확인)
- 카드별 "삭제" 버튼 → `removeFromWishlist(id)` + 토스트
- 전체 삭제 버튼 (확인 절차 포함, 예: `window.confirm`)
- 빈 상태 UI: "찜한 상품이 없습니다. 카탈로그에서 상품을 찜해 보세요." + 카탈로그 이동 버튼

### 4. 라우팅 (`front/src/App.jsx`)
- `<Route path="/mypage" element={<MyPage />} />` 추가
- `/wishlist`는 Header가 이미 `navigate('/wishlist')`를 호출하므로, `<Route path="/wishlist" element={<Navigate to="/mypage?tab=wishlist" replace />} />`로 처리

### 5. 스타일
- `front/src/pages/styles/MyPage.styles.js` 신규 (기존 `CatalogPage.styles.js`, `JournalPage.styles.js` 패턴 준수)
- 칩 스타일은 `components/Auth/styles/AuthForm.styles.js`의 `Chip`, `ChipGroup`, `ChipSection`을 재사용하거나 공통 위치로 이동 검토
- 탭 UI는 기존 공통 컴포넌트에 없으므로 `MyPage.styles.js`에 구현

## ❓ 작업 전 확인이 필요한 항목
1. **위시리스트 영속화 여부**: 현재 메모리 상태라 새로고침 시 사라짐. 서버 저장(예: `wishlist` 테이블 신규)이 필요한지 여부 (기본값: 이번 범위 제외)

4. **`/wishlist` 처리 방식**: 리다이렉트(기본값) vs 별도 페이지 신규
