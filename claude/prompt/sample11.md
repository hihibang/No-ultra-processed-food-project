우리 서비스(PingPong)에 시간이 쌓일수록 정교해지는 사용자 간/아이템 간 행동 데이터 기반 ""협업 필터링(Collaborative Filtering)"" 추천 엔진과 프론트엔드 UI 4종을 한 번에 구축해줘.
먼저 백엔드와 프론트엔드 프로젝트 전체 구조를 스캔해서 기존 DB 모델, 인증 방식(access_token), API 클라이언트(`rt` 등), 스타일 시스템(`styled-components`)을 파악한 뒤 백엔드와 프론트엔드를 완벽한 계약(API 스키마 일치) 하에 통합 구현해줘.

==================================================
[PART 1] 백엔드: DB 로그 정비 + 협업 필터링 엔진 + API 4종
==================================================
1. **통합 행동 로그(Implicit Feedback) 구조 정비**
   - 기존 유저, 상품, 일반 레시피, 인플루언서, 찜/마이페이지 로그(`mypage/logs`) 모델을 확인하고, 행동 가중치(조회: 1점, 비교/클릭: 2점, 찜/저장: 5점) 및 최근 행동 우대 시간 감쇠(Time Decay)를 계산할 수 있도록 정비해줘.
   - 행동 이벤트 기록 API (`POST /api/recommendations/interactions`)를 만들어 프론트에서 상품 찜, 상품 비교, 레시피 저장, 인플루언서 찜이 일어날 때 로그가 누적되게 해줘.

2. **협업 필터링 추천 엔진 (`recommendation_service.py`) 구현**
   - `numpy` / `scikit-learn`의 코사인 유사도(`cosine_similarity`)를 활용하고, 초기 데이터 부족(Cold Start) 시에도 에러 없이 콘텐츠 점수(건강 점수, 카테고리, 주방도구·식이제한 프로필)로 자연스럽게 Fallback 되도록 하이브리드 로직을 구현해줘.

3. **추천 API 4종 엔드포인트 구현 (`routers/recommendations.py`)**
   - **① `POST /api/recommendations/recipe-products` (레시피 맞춤 상품 추천)**
     - 입력: `{ recipe_title: str, ingredients: list[str] | str }` (로그인 시 헤더 토큰에서 유저 식별)
     - 로직: 레시피 재료와 매칭되는 상품 DB 항목을 찾되, ① 현재 유저가 찜한 상품 최우선(`is_wished: true`), ② 해당 레시피/재료를 선호하는 유사 유저들이 함께 찜한 상품(CF 점수), ③ 건강 점수(NOVA/영양점수) 순으로 상위 3~4개 반환.
   - **② `GET /api/recommendations/similar-users/recipes` (유사 취향 유저 저장 레시피 추천)**
     - 로직: 현재 유저의 취향 프로필(조리도구, 선호 요리, 식이제한) + 저장/찜한 레시피 상호작용 벡터로 코사인 유사도 Top-K 이웃 유저를 찾고, 이웃이 저장했지만 현재 유저가 아직 보지 않은 레시피 Top 6 반환 (일치율/추천 사유 배지 텍스트 포함).
   - **③ `GET /api/recommendations/cross-domain` (인플루언서·레시피 팬덤 Cross-Domain CF)**
     - 쿼리: `?target_type=influencer|recipe&target_id=...`
     - 로직: 해당 인플루언서를 찜했거나 해당 일반 레시피를 찜한 유저 집단을 추출하고, 이 집단이 교차로 많이 찜한 **연관 상품 Top 4**와 **연관 레시피 Top 4** 반환.
   - **④ `GET /api/recommendations/products/{product_id}/compare` (스마트 상품 비교 CF)**
     - 로직:
       (A) 동일 카테고리/품목 내에서 건강 점수(NOVA/영양점수)가 유사한 대체 상품 2~3개 추출.
       (B) 기준 상품을 찜하거나 비교한 고객들의 행동 행렬(Item-Based CF)을 분석해 `"이 상품을 찜한 고객의 OO%가 선택한 상품"` 선택 비율(`selection_rate`)과 함께 반환.

4. **시드/테스트 검증**
   - 추천 로직이 빈 배열만 뱉지 않고 실제 데이터를 기반으로 동작하는지 확인할 수 있도록 기존 더미/시드 데이터 또는 테스트 스크립트까지 점검해줘.

==================================================
[PART 2] 프론트엔드: 4대 추천 UI 및 행동 로그 연동
==================================================
기존 디자인 톤(그린 포인트 컬러, 카드 UI, styled-components)을 유지하면서 아래 4곳에 백엔드 API를 연동해줘.

1. **AI 챗봇 답변 카드 하단 (`AIChatPage.jsx`) - ① 레시피 맞춤 상품 추천**
   - AI가 레시피를 추천해 줄 때마다 답변 카드 바로 아래에 `[이 요리에 딱 맞는 추천 상품]` 섹션을 렌더링해줘.
   - 답변 텍스트(또는 제목/재료)를 기반으로 `POST /api/recommendations/recipe-products`를 호출하고, 내가 찜한 상품에는 `❤️ 내가 찜한 재료`, 유사 유저 추천 상품에는 `👥 유사 취향 Pick` 배지를 붙여줘. (상품 클릭 시 상세 이동 또는 바로 찜하기 지원)

2. **홈 화면 & 챗봇 초기 화면 - ② 나와 비슷한 취향의 유저가 저장한 레시피**
   - 홈 화면 메인 영역과 AI 챗봇의 대화가 비어 있는 초기 화면 하단에 `[나와 취향·주방이 비슷한 유저들이 저장한 레시피]` 섹션을 추가해줘.
   - `GET /api/recommendations/similar-users/recipes`를 연동해 추천 사유 배지와 함께 카드로 보여주고, 클릭 시 상세 레시피를 보거나 챗봇에 바로 물어볼 수 있게 연결해줘.

3. **인플루언서 페이지 & 일반 레시피 상세 페이지 - ③ 팬덤 Cross-Domain 추천**
   - 인플루언서 피드/상세 하단과 일반 레시피 상세 페이지(챗봇 외 일반 레시피) 하단에 `[이 인플루언서(레시피)를 좋아하는 분들이 함께 찜한 상품 & 레시피]` 섹션을 추가해줘.
   - `GET /api/recommendations/cross-domain`을 호출해 연관 상품 탭/리스트와 연관 레시피 리스트를 함께 보여줘.

4. **상품 목록 '비슷한 상품 비교' 화면 - ④ 스마트 상품 비교**
   - 기존 `비슷한 상품 비교` 버튼을 눌렀을 때 열리는 비교 모달/페이지에 `GET /api/recommendations/products/{product_id}/compare` 데이터를 연동해줘.
   - 건강 점수가 비슷한 동종 제품 스펙 비교표와 함께 `"이 상품을 찜한 고객의 OO%가 이 제품을 선택했어요"` 배지 및 선택률 게이지 바를 시각적으로 표시하고, 비교 화면에서 상품을 클릭·찜할 때 `POST /api/recommendations/interactions` 로그도 기록되도록 연결해줘.

작업 완료 후 백엔드 서버와 프론트엔드 빌드/실행에 문법·타입 오류가 없는지 최종 확인해줘.
