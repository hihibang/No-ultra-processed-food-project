# 작업계획 8: 위시리스트 DB 연동 & 비교함 / 비교 히스토리 로그

원본 요구사항: `claude/sample8.md`

---

## 0. 전제 및 확정 사항

- DB 테이블은 이미 생성되어 있다고 가정한다 (직접 생성하지 않음).
  - `wishlists (wishlist_id, user_id, food_id, created_at)`, `(user_id, food_id)` UNIQUE
  - `comparison_logs (comparison_id, user_id, product_ids JSON, created_at)`
- **확정**: `food_id`는 `active_food_catalog`를 참조한다.
  - `active_food_catalog`의 PK는 `report_no`이다 (`server/food_db.sql`).
  - 확인 필요: `report_no`의 자료형이 `int`가 아니면 요구사항의 `food_id(int)` 스키마와 맞지 않으므로 구현 전에 자료형을 확인하고 스키마를 맞춘다.
- **확정**: 비로그인 상태에서 하트 버튼을 누르면 로그인하라는 안내를 띄운다.
- **확정**: 비교함 클릭 시 비교 페이지로 이동한다.
- 기존 코드 현황 (작업 전 파악 내용):
  - `front/src/contexts/CompareContext.jsx`: 이미 존재. `compareItems`, `addToCompare`, `removeFromCompare`, `clearCompare`, `isInCompare` 보유. `localStorage` 미적용, 백엔드 연동 없음. 요구사항의 `compareList` 명칭과 다르므로 기존 명칭 유지 여부를 결정한다.
  - `front/src/contexts/CartContext.jsx`: 장바구니와 함께 `wishlist` 로컬 state가 이미 있음. DB 동기화로 전환 대상.
  - `server/main.py`: `food_router`, `auth_router`만 등록되어 있음. 두 라우터 추가 필요.
  - `server/models`, `server/routes`, `server/schemas`에는 wishlist/comparison 관련 파일이 없음 (신규 생성).
  - `users` 테이블 존재. 인증은 `auth_routes.py` 기준으로 user_id를 얻는 방식을 따른다.

## 1. 백엔드 (`server/`)

### 1-1. Schemas (신규)
- [ ] `schemas/wishlist_schema.py`
  - `WishlistCreateRequest`: `food_id: int` (report_no 자료형에 맞춤)
  - `WishlistResponse`: `wishlist_id: int`, `user_id: int`, `food_id: int`, `food_details: Optional[dict]`
- [ ] `schemas/comparison_schema.py`
  - `ComparisonLogCreateRequest`: `product_ids: List[int]`
  - `ComparisonLogResponse`: `comparison_id: int`, `user_id: int`, `product_ids: List[int]`, `foods: List[dict]`, `created_at: str`

### 1-2. Models (신규)
- [ ] `models/wishlist_model.py` (`WishlistModel`, SQL `text()` + `AsyncSession`)
  - `get_user_wishlist(user_id)`: `wishlists`를 `active_food_catalog`와 `food_id = report_no`로 JOIN해 상세 정보 포함
  - `add_wishlist(user_id, food_id)`: UNIQUE 위반 시 예외를 라우트에서 409로 변환
  - `remove_wishlist(user_id, food_id)`: 삭제된 행 수 반환 (0이면 404 처리)
- [ ] `models/comparison_model.py` (`ComparisonModel`)
  - `save_log(user_id, product_ids)`: `product_ids`는 JSON으로 저장
  - `get_logs_by_user(user_id)`: `created_at DESC` 정렬, 각 로그의 `product_ids`를 `active_food_catalog`에서 조회해 `foods` 구성

### 1-3. Routes (신규)
- [ ] `routes/wishlist_routes.py`
  - `GET /api/wishlist`: 사용자 찜 목록 + 상세 정보
  - `POST /api/wishlist`: 찜 추가, 중복 시 **409**
  - `DELETE /api/wishlist/{food_id}`: 찜 해제
- [ ] `routes/comparison_routes.py`
  - `GET /api/comparisons`: 사용자 비교 기록 목록
  - `POST /api/comparisons`: 비교 내역 로그 저장
- [ ] 모든 엔드포인트는 로그인 사용자 기준으로 동작 (타 사용자 데이터 접근 차단, 비로그인 시 401)

### 1-4. 등록
- [ ] `server/main.py`에 `wishlist_router`, `comparison_router` `include_router` 추가

## 3. 검증 체크리스트

- [ ] 찜 추가 → 새로고침 후에도 유지 (DB 반영)
- [ ] 같은 상품 중복 찜 시 409 응답 및 토스트 안내
- [ ] 찜 해제 후 목록에서 제거
- [ ] 비교함 추가/삭제 → 헤더 배지 개수 일치, localStorage 복원
- [ ] 헤더 비교함 클릭 → 비교 페이지 이동
- [ ] 비교 실행 시 `comparison_logs` 행 생성, MyPage 비교 히스토리에 노출
- [ ] 다른 사용자의 찜/비교 기록이 보이지 않음
- [ ] 비로그인 상태에서 하트 클릭 시 로그인 안내 표시, API 직접 호출 시 401
