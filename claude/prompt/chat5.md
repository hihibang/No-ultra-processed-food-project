현재 레시피 챗봇 프론트엔드에서 "다른 레시피 추천하기" 퀵 액션 버튼을 누를 때 발생하는 문제를 해결하려고 해.
기존에는 매번 새로운 질문을 백엔드/n8n으로 보내서 같은 레시피가 반복되거나, 계속 누르면 원래 재료와 무관한 레시피가 추천되는 문제가 있었어.

아래 요구사항에 맞춰 프론트엔드 상태(State) 관리와 API 호출 로직을 수정해줘.

### 구현 요구사항
1. **대화방(세션) 단위 레시피 후보군 캐싱 (`cachedRecipes` & `recipeIndex`)**
   - 사용자가 직접 새로운 질문(텍스트 입력)을 보낼 때는 기존처럼 검색 API를 호출해.
   - 이때 응답 JSON에 함께 내려오는 `recipes` 배열(상위 추천 레시피 후보군)을 현재 대화창의 State(`cachedRecipes`)에 저장하고, 현재 인덱스(`recipeIndex = 0`)로 초기화해.
   - 사용자가 대화창을 나가거나, 새로운 검색어를 직접 입력하기 전까지는 이 `cachedRecipes` 배열을 고정 유지해.

2. **"다른 레시피 추천하기" 버튼 클릭 시 동작 변경**
   - DB/벡터 검색을 새로 돌리지 말고, 저장해 둔 `cachedRecipes`에서 다음 순번(`nextIndex = recipeIndex + 1`)의 레시피 1개를 꺼내.
   - 꺼낸 단일 레시피 객체(`targetRecipe`)와 기존 `profile`, `sessionId`를 담아 백엔드/n8n으로 요청을 보내서 해당 레시피에 대한 조리법 설명만 생성하도록 해줘. (예: request body에 `targetRecipe: cachedRecipes[nextIndex]` 포함)
   - 요청 성공 시 `recipeIndex`를 `nextIndex`로 업데이트해.

3. **후보군 소진 시 예외 처리**
   - 만약 `nextIndex >= cachedRecipes.length`가 되어 더 이상 꺼낼 후보 레시피가 없다면, API를 호출하지 않고 챗봇 메시지로 `"처음 찾은 맞춤 레시피 후보를 모두 보여드렸어요! 다른 재료를 입력해 보시겠어요?"`라고 안내해줘.

위 로직이 반영된 프론트엔드 상태 관리 및 이벤트 핸들러 코드를 작성해줘.
