# 인증(Auth) 모듈 구축 및 회원가입 연동 작업계획

## 📋 프로젝트 개요
- **원본 요구사항**: `claude/sample6.md`
- **작업 범위**: 백엔드 Auth 모듈(schemas / models / routes) 신규 구축 + 프론트엔드 회원가입 2단계 폼 연동
- **백엔드**: FastAPI + SQLAlchemy(aiomysql), `server/`
- **프론트엔드**: React(Vite), styled 방식의 `*.styles.js` 분리 구조, `front/`
- **전제**: DB DDL은 이미 실행되어 `users` 테이블이 존재함

## 🎯 작업 범위 및 제약사항

### 범위 제한
- ✅ `server/schemas/user_schema.py`, `server/models/user_model.py`, `server/routes/auth_routes.py` 신규 생성
- ✅ `server/main.py`에 auth 라우터 등록만 추가 (기존 food 라우터 변경 없음)
- ✅ `front/src/components/Auth/` 하위 회원가입 관련 파일 수정 (`SignupForm.jsx`, 필요 시 `AuthModal.jsx`, `styles/AuthForm.styles.js`)
- ✅ `front/src/contexts/AuthContext.jsx`, `front/src/hooks/useAuth.js`에 API 연동에 필요한 최소 변경
- ❌ DB DDL 변경/재실행 금지 (이미 실행 완료)
- ❌ 기존 food 검색/상세 API 동작 변경 금지
- ❌ 로그인 UI 전면 개편은 범위 외 (`/api/auth/login` 백엔드 구현까지만 포함, 프론트 로그인 API 연동은 필요 시 별도 확인)

### 핵심 제약
- 비밀번호는 평문 저장 금지 (bcrypt 해시 저장)
- 응답에 `password`(해시 포함) 필드 노출 금지
- SQL은 기존 방식대로 `text()` + 바인드 파라미터 사용 (문자열 포매팅 금지)
- 주석/에러 메시지는 기존 파일처럼 한글 사용

## 🏗️ 백엔드 작업

### 1. 의존성
- `server/requirements.txt`에 `bcrypt` 추가
- 토큰 방식(JWT 등)을 쓸 경우 `pyjwt` 추가 여부를 작업 전 확인 (미확인 시 세션/토큰 발급은 보류하고 `TokenResponse` 구조만 우선 정의)

### 2. schemas (`server/schemas/user_schema.py`)
- `UserSignUpRequest`
  - `email: EmailStr` (또는 `str` + 간단 검증; `email-validator` 설치 필요 여부 확인)
  - `password: str` (최소 길이 검증)
  - `name: str`
  - `appliances: List[str]`
  - `preferences: List[str]`
  - `cooking_level: str`
- `UserLoginRequest`: `email`, `password`
- `UserResponse`: 공개 가능한 유저 정보만 (id, email, name, appliances, preferences, cooking_level)
- `TokenResponse`: `access_token`, `token_type`, `user: UserResponse`

### 3. models (`server/models/user_model.py`)
- `UserModel` 정적 메서드로 구현
  - `find_by_email(session, email)` : 이메일 중복 체크 및 로그인 조회
  - `create_user(session, data)` : INSERT
    - 비밀번호는 bcrypt 해시 후 저장
    - `appliances`, `preferences`는 `json.dumps(..., ensure_ascii=False)`로 직렬화
  - `verify_password(plain, hashed)` : bcrypt 검증
- 조회 결과의 JSON 컬럼은 `json.loads`로 역직렬화해 반환 (컬럼이 TEXT인 경우 대응)
- INSERT 후 `commit` 누락 주의 (`AsyncSession` 사용)

### 4. routes (`server/routes/auth_routes.py`)
- `router = APIRouter(prefix="/api/auth", tags=["Auth"])`
- `POST /api/auth/signup`
  1. `find_by_email`로 중복 확인 → 중복 시 `HTTPException(status_code=409, detail="이미 가입된 이메일입니다.")`
  2. `create_user` 호출
  3. `UserResponse` 반환 (201)
- `POST /api/auth/login`
  1. 이메일로 사용자 조회 → 없거나 비밀번호 불일치 시 동일한 메시지로 `401` (이메일 존재 여부 노출 방지)
  2. 성공 시 `TokenResponse` 반환
- 의존성 주입은 기존처럼 `db: AsyncSession = Depends(get_db)` 사용

### 5. 라우터 등록 (`server/main.py`)
- `from routes.auth_routes import router as auth_router`
- `app.include_router(auth_router)`

### 6. 백엔드 검증
- `uvicorn main:app --reload` 기동 확인 (`server/` 디렉토리에서)
- `/docs`에서 signup/login 호출
  - 정상 가입 → 201 + 비밀번호 미노출
  - 동일 이메일 재가입 → 409
  - 잘못된 비밀번호 로그인 → 401
- DB에서 `password` 컬럼이 해시 문자열인지 확인

## 🎨 프론트엔드 작업

### 1. SignupForm을 2단계(Multi-step) 폼으로 개편 (`front/src/components/Auth/SignupForm.jsx`)

**Step 1 — 기본 정보**
- 입력: 이름, 이메일, 비밀번호, 비밀번호 확인, 약관동의(체크박스)
- 유효성 검사: 필수값, 이메일 형식, 비밀번호 길이, 비밀번호 일치, 약관 동의
- "다음" 버튼 → 검사 통과 시 Step 2 이동, 실패 시 필드별 메시지 표시

**Step 2 — 생활 환경 정보**
- 보유 주방기기 칩 토글 (전자레인지, 에어프라이어, 인덕션 등)
- 선호 요리 스타일 칩 토글
- 요리 숙련도 선택 (`cooking_level`)
- 버튼: `← 이전` (Step 1 복귀, 입력값 유지) / `회원가입 완료`

### 2. API 연동
- `회원가입 완료` 클릭 시 `POST /api/auth/signup` 호출
  - 요청 본문: `{ email, password, name, appliances, preferences, cooking_level }`
  - `passwordConfirm`, `agree`는 전송하지 않음
- 호출 중 버튼 비활성화 (`isLoading` 기존 패턴 활용)
- API base URL은 기존 food API 호출 방식과 동일하게 맞출 것 (`front/src`에서 기존 fetch 위치 확인 후 통일)

### 3. 성공/실패 처리
- 성공: `useToast`로 성공 토스트 표시 → 모달 닫기 → 로그인 탭으로 전환 (`onSwitchToLogin` 활용)
- 실패: 서버 `detail` 메시지를 사용자 친화적 문구로 매핑
  - 409 → "이미 가입된 이메일입니다. 로그인을 시도해 주세요."
  - 네트워크 오류 → "서버에 연결할 수 없습니다. 잠시 후 다시 시도해 주세요."
  - 기타 → "회원가입에 실패했습니다. 다시 시도해 주세요."
- 실패 시 Step 2에 머물며 입력값 유지

### 4. 스타일
- 신규 UI 요소(스텝 표시, 칩 토글, 이전/완료 버튼 그룹)는 `styles/AuthForm.styles.js`에 추가
- 기존 `Button`, `Input`, `FormGroup` 등 공통 컴포넌트 재사용
